BotPicks Architecture Master Document

Purpose

This document consolidates the complete architectural design of the
BotPicks system. It serves as the central technical reference for the
project.

System Vision

BotPicks is designed as an autonomous sports intelligence platform
capable of:

-   Discovering sports data sources automatically
-   Modeling sports events and betting markets
-   Training predictive models
-   Running simulations and strategy optimization
-   Generating betting picks
-   Managing bankrolls across multiple sportsbooks
-   Interacting with users via Telegram conversational AI
-   Learning and evolving autonomously

Core Architectural Principles

1.  Modularity Every capability is encapsulated in engines organized
    into layers and macro systems.

2.  Autonomous Operation The system continuously runs pipelines to
    collect data, train models, simulate outcomes, generate strategies,
    and improve performance.

3.  Engine Standardization All engines follow a universal interface
    enabling discovery, orchestration, monitoring, and autonomous
    repair.

4.  Pipeline Orchestration Engines are connected through pipelines that
    define data and decision flows.

5.  Evolution and Extensibility The architecture allows generation of
    new engines and modules without breaking the system.

Core System Responsibilities

The Autonomous Core System acts as the operating system of BotPicks.

Responsibilities include:

-   Engine discovery
-   Module registration
-   Pipeline orchestration
-   Task scheduling
-   State persistence
-   System monitoring
-   Engine auto-repair
-   Autonomous evolution

Universal Engine System

Each engine follows a common contract:

Fields: - name - macro_system - layer - version - dependencies -
schedule

Core methods: - initialize() - execute() - learn() - health_check()

This structure enables the core system to manage thousands of engines
consistently.

Pipeline Architecture

Pipelines connect engines into executable flows.

Primary pipelines:

DATA_PIPELINE MODEL_PIPELINE SIMULATION_PIPELINE STRATEGY_PIPELINE
PICK_PIPELINE NOTIFICATION_PIPELINE MONTHLY_AUDIT_PIPELINE

Pipelines can be triggered by:

-   Scheduler
-   Data events
-   Telegram commands
-   Autonomous learning modules

Universal Data System

Data architecture consists of:

1.  Raw Data Layer
2.  Data Lake Layer
3.  Normalized Data Layer
4.  Feature Store Layer
5.  Dataset Layer
6.  Historical Archive Layer
7.  Data Access Layer
8.  Metadata & Catalog Layer

This design supports large-scale analytics, ML training, and
simulations.

Execution Architecture (GitHub Actions)

The system runs continuously using scheduled jobs:

Workers:

-   data_worker
-   market_worker
-   model_worker
-   simulation_worker
-   strategy_worker
-   notification_worker
-   system_worker

Jobs run at intervals such as:

-   every 5 minutes
-   hourly
-   daily
-   monthly

System state is stored to allow persistent operation across executions.

Conversational Copilot

Telegram acts as the primary user interface.

Capabilities:

-   natural language queries
-   strategy generation
-   match analysis
-   simulation requests
-   bankroll monitoring
-   system administration (admin only)

Bankroll Intelligence

The system manages betting capital across sportsbooks.

Supported features:

-   global bankroll
-   sportsbook-specific bankrolls
-   bookmaker discovery
-   bookmaker activation / deactivation
-   bet allocation optimization

Autonomous Intelligence

The system continuously improves through:

-   hypothesis generation
-   automated experimentation
-   model improvement
-   strategy evolution

Final Architecture Goal

BotPicks aims to operate as a fully autonomous sports intelligence
platform capable of discovering insights, optimizing strategies, and
assisting users through an intelligent conversational interface.

This document serves as the foundational architecture reference for
development, maintenance, and long-term evolution of the system.
